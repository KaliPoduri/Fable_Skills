# CWE Top 25 (2025 edition) — distilled for code review

Source: 2025 CWE Top 25 Most Dangerous Software Weaknesses,
https://cwe.mitre.org/top25/archive/2025/2025_cwe_top25.html (full list
verified 2026-07-06; released with CISA 2025-12-11, based on CVE records
June 2024–June 2025). Use this file to assign CWE IDs and ranks to
findings. If a real weakness is not on this list, assign its correct CWE
ID anyway and note it is outside the Top 25.

## Review indicators by group

### Injection and output handling (CWE-79, 89, 78, 77, 94)
- String concatenation/interpolation of request data into SQL, shell
  commands, templates, or eval.
- HTML/JS emitted without context-aware encoding; `innerHTML` with user
  content.
- Distinguish CWE-78 (OS command via shell metacharacters) from CWE-77
  (generic command language) and CWE-94 (generated source code / eval).

### Authorization and access (CWE-862, 863, 284, 639, 306)
- CWE-862: no authorization check at all on an action.
- CWE-863: a check exists but is wrong (wrong role, wrong object, client
  data trusted).
- CWE-639: record looked up purely by a user-supplied key/ID — change the
  ID, get someone else's data.
- CWE-306: security-critical function reachable with no authentication.
- CWE-284: broader/parent class — prefer the more specific CWE above when
  it fits.

### Request forgery (CWE-352, 918)
- CWE-352: state-changing endpoints without CSRF token/SameSite defense;
  GET requests with side effects.
- CWE-918: outbound URL built from user input (webhooks, importers, PDF
  renderers, image fetchers) without scheme/host allow-listing; redirects
  followed blindly; access to link-local metadata addresses possible.

### Memory safety (CWE-787, 125, 416, 120, 121, 122, 476)
Native code (C/C++/unsafe blocks) only, plus CWE-476 analogues in managed
languages:
- Unchecked lengths into fixed buffers (strcpy/sprintf/memcpy with
  attacker-influenced size) → 120/121/122/787.
- Index arithmetic from input without bounds checks → 125/787.
- Manual free + continued use, double free, dangling callbacks → 416.
- Pointer/optional dereferenced on error paths → 476.

### Input, files, deserialization (CWE-20, 22, 434, 502)
- CWE-20: use when input is not validated at the trust boundary and no
  more specific injection CWE applies.
- CWE-22: user input in file paths; check canonicalize-then-verify order.
- CWE-434: uploads validated by extension or client MIME type only;
  files stored under the web root; no content verification.
- CWE-502: native deserializers (pickle, ObjectInputStream, unserialize,
  unsafe YAML) on untrusted bytes.

### Exposure and resources (CWE-200, 770)
- CWE-200: stack traces/SQL/internal paths to clients, secrets or PII in
  logs, verbose diagnostics endpoints, overly detailed auth errors.
- CWE-770: attacker-controlled sizes/counts without caps — uploads,
  pagination limits, zip expansion, regex on unbounded input, unbounded
  concurrency or queue growth.
